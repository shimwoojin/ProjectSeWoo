# 스팀 설정 — 앱 페이지 / 스토어 페이지

관련: [A12 빌드·배포](A12-BUILD.md) / [A8 스팀](A8-STEAM.md) / [확정 기획서](기획확정-일감분배-260907.md) §7-2 · §7-6 · §11 (C1 · C2)

> **빌드를 올리는 것과 실행되게 하는 것은 다른 일이다.** [A12](A12-BUILD.md) 는
> depot 에 무엇을 올리는지까지만 다룬다. **스팀이 그걸 어떻게 설치하고 실행하는지는
> 저장소에 없고 파트너 사이트에만 있다** — 그게 이 문서다.
>
> 파트너 사이트의 메뉴 이름은 바뀔 수 있다. 여기 적은 것은 **무엇을 왜 그 값으로
> 두는가**이고, 정확한 라벨은 현장에서 찾는다.

## 1. 앱 페이지 — 설치·실행 방식

### 1-1. 실행 옵션 (이게 없으면 아예 안 뜬다)

| 항목 | 값 |
|---|---|
| 실행 파일 | `PunchMonkey.exe` |
| 작업 디렉터리 | **비워둠** |
| 운영체제 | Windows |
| 인자 | 없음 |

**설정 전에는 스팀이 "잘못된 게임 구성" 을 띄운다.** depot 에 파일이 다 올라가
있어도, **스팀은 그중 뭘 실행해야 하는지 모른다.** 업로드가 성공했다는 것과
실행된다는 것이 별개라는 걸 여기서 처음 만난다 — 2026-09-16 에 실제로 밟았다.

**작업 디렉터리를 비워도 되는 이유**는 우리 코드가 경로를 전부 **exe 위치 기준**으로
잡기 때문이다. `HelperInputSource.ResolveHelperPath()` 가 `OS.GetExecutablePath()` 의
폴더에서 `InputHelper.exe` 를 찾고, `steam_api64.dll` 도 같은 자리다. A8 이
`steam_appid.txt`(작업 디렉터리 의존) 대신 환경변수로 간 것도 같은 이유였다 —
**그 결정들이 여기서 "설정할 게 하나 줄었다" 로 돌아온다.**

> 설정을 바꾼 뒤에는 **게시(Publish)** 해야 적용된다. SteamPipe 빌드 업로드와 앱
> 설정 게시는 **별개 경로**다 — 빌드가 올라가 있어도 설정은 게시 전까지 안 붙는다.

### 1-2. Steam Cloud — **끈다**

직관과 반대라 이유를 남긴다. 클라우드 동기화는 **게임을 종료할 때** 도는 것을
전제한다. **우리는 종료를 안 하는 앱이다** — 며칠씩 켜져 있고, 자동 시작(A6)을
켜면 부팅부터 뜬다.

A3 가 세이브에 원자적 쓰기(`File.Move(overwrite)`)까지 넣어둔 파일에 Cloud 가
끼면 충돌 해소가 복잡해진다. 얻는 것은 "다른 PC 에서 이어하기" 인데 상주
오버레이는 보통 한 PC 에서 쓴다.

**나중에 켜는 건 쉽고 끄는 건 어렵다.** 유저 세이브가 클라우드에 올라간 뒤에
끄면 그때부터가 문제다.

### 1-3. VAC — **절대 켜지 않는다**

**전역 키보드 RawInput 을 읽는 별도 프로세스가 있는 앱이다.** VAC 대상으로
등록하는 순간 그 조합이 유저에게도 안티치트에게도 최악의 신호가 된다.
기획서 §7-2 가 A13 에 "Vanguard·EAC 켠 상태 충돌 검증" 을 넣은 것과 같은 축이고,
**이쪽은 검증이 아니라 그냥 켜지 않으면 되는 일이다.**

### 1-4. Steam Overlay — 켜되 **A9 에서 검증**

A9~A11 의 친구 초대가 오버레이 기반이라 **필요하다.** 다만 공짜가 아니다.

우리 창은 **per-pixel 투명 + always-on-top + 클릭 통과**이고 렌더러는 d3d12 다.
**오버레이 후킹이 스왑체인에 붙으면 투명이 깨질 수 있다** — A7 §3-2 에서 플리커를
검증했던 바로 그 경로이고, 그 Go 판정은 **오버레이가 안 붙은 상태에서 받은 것**이다.

> **A9 착수 시 검증 항목**: 오버레이를 켠 채로 마스코트 주변 투명이 유지되는가.
> 깨지면 초대 UI 를 룸 코드 복사(B12)로 대체하는 선택지가 있다.

### 1-5. 나머지

| 설정 | 값 | 이유 |
|---|---|---|
| Steam Input | 끈다 | 게임패드를 쓰지 않는다 |
| 재배포 런타임 | **아무것도 추가하지 않는다** | Godot 이 .NET 을 `data_.../` 에 동봉하고 InputHelper 는 NativeAOT 다 (A12 §2). **.NET 재배포를 걸었으면 설치가 길어지고 실패 지점이 하나 늘었다** — A12 의 AOT 결정이 여기서 한 번 더 값을 한다 |
| 설치 폴더명 | `PunchMonkey` | |
| 브랜치 | `beta` 에 비밀번호 | 금요일 데모·주말 실사용용 (기획서 §8-3). 공개 전까지 잠가 둔다 |
| DLC / 인앱 결제 | 없음 | 바나나는 게임 내 재화다. 실제 결제가 아니다 |

## 2. 스토어 페이지

### 2-1. 앱 유형은 Game

상주 유틸리티처럼 보이지만 **재화·상점·도감·도전과제·멀티가 있는 게임 루프**다.
Application 으로 등록하면 그 기능들의 노출이 어색해진다.

### 2-2. 개인정보 문구 — 이 페이지에서 가장 중요한 항목

기획서 §7-6 이 확정한 문구를 **그대로** 쓴다. 게임 내 최초 실행(B15)에도 같은
문구가 나가야 한다.

> 이 게임은 타이핑과 마우스 클릭의 **횟수**만 셉니다. 어떤 키를 눌렀는지, 어떤
> 버튼을 눌렀는지, 마우스가 어디에 있는지 읽지 않고, 저장하지 않으며, 외부로
> 전송하지 않습니다.

**설명 맨 위, 접히기 전에 둔다.** "키보드 입력을 읽는 상주 앱" 은 리뷰 한 줄로
죽는 카테고리다. 기획서 §10 이 컷 라인에서 개인정보 문구를 **"절대 자르지 않는
것"** 에 넣은 이유가 이것이다.

**그리고 이건 마케팅 문구가 아니라 검증 가능한 주장이다.**
`platform/InputHelper/RawKeyboardCounter.cs` 는 `RAWKEYBOARD`/`RAWMOUSE` 를 통째로
마샬링하는 구조체를 만들지 않고, 오프셋으로 `Flags`(누름/뗌)와 `usButtonFlags`
(버튼이 눌렸는가)만 읽는다. **키 코드도 커서 좌표도 필드로 존재조차 하지 않는다.**
마우스 버튼은 눌림 비트를 합친 마스크와 `!= 0` 비교 한 번만 하므로 **어느 버튼인지도
모른다.** 그 파일 주석이 이유까지 적어 뒀다 — 구조체를 만들면 "안 읽는다" 가 규율의
문제가 되기 때문이다. 그러니 **강하게 써도 된다.**

> **2026-09-19 변경.** 마우스 클릭이 타수에 포함되면서(기획서 §6) 문구를 같이
> 고쳤다. 스토어 페이지 공개 전이라 나간 약속을 고치는 일은 아니다. 커서 좌표를
> 읽지 않는다는 약속이 새로 들어가 **범위는 넓어졌지만 약속은 하나 늘었다.**

§7-6 이 요구한 **멀티 전송 데이터 목록**도 같이 명시한다:

> 멀티플레이 중 전송: 타건 발생 여부 / 수확 이벤트 / 누적 타수 / 장착 정보. 그 외 없음.

### 2-3. 상주 앱이라는 것을 숨기지 않는다

"항상 켜두는 오버레이" 가 핵심 가치인데, **모르고 산 사람이 환불하면 리뷰가
나빠진다.** 첫 문단에 명시하는 쪽이 장기적으로 이득이다.

### 2-4. 시스템 요구사항 — 실측 기반

| | |
|---|---|
| OS | Windows 10 64-bit |
| **그래픽** | **DirectX 12 지원 GPU** |
| 메모리 | 1 GB (실측 `PrivWS` **239MB**, A7 §3-2) |
| 저장공간 | 300 MB (빌드 183MB, A12 §5-1) |

**DX12 요구가 실제 배제 요인이다.** Forward+/d3d12 로 확정했고 A7 §5 에서
`gl_compatibility` 재도전 카드를 철회했으므로, 오래된 GPU 는 못 돈다.
**정직하게 적는 편이 환불보다 싸다.**

## 4. 상주 앱이라 업데이트가 늦게 붙는다

스팀은 게임이 **꺼져 있을 때** 업데이트한다. 우리는 며칠씩 켜져 있고 자동
시작까지 켜면 더 길다. **빌드를 올렸다고 유저가 받은 것이 아니다.**

출시 후 핫픽스를 낼 때 체감하게 되는 항목이고, A14(첫 실행 플로우)에서 같이
본다 — 앱이 자기 버전과 최신 버전을 비교해 "재시작하면 업데이트됩니다" 를
알려주는 정도가 현실적인 대응이다.
