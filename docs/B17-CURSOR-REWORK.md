| 장식 | 잔상 6 + 바닥 4 (그림 한 장씩) | **1칸.** 빛 효과 · 파티클 · 엉뚱한 물건 등 종류별 동작 |

### 1-1. 왜 컷아웃 리그인가

Spine 은 편집기 라이선스가 필요하고, C# 프로젝트에 런타임을 붙이려면 엔진 빌드를 바꿔야 할 수 있다. 프레임
애니메이션은 상태 × 프레임 × 원숭이 종류만큼 그림이 필요하고, AI 생성은 프레임 사이 일관성이 가장 약하다(§6-1
의 결함이 그 예다). 컷아웃은 Godot 기본 기능(부위 노드 + 회전 축)만으로 되고, 움직임 대부분을 **코드가 만든다**
— 반응형이라는 요구에 가장 잘 맞는다. 원숭이 종류는 **부위 그림만 바꿔 끼운다.**

## 2. 아이템 목록 한 곳으로 (`items.json`)

지금 장식 하나를 늘리려면 네 곳을 손으로 맞춰야 한다 — `game/shop/ShopCatalog.cs`, `server/src/catalog.ts`,
`platform/SteamInventoryService.cs` 의 id↔itemdefid 표, `server/steam-inventory/itemdefs.json`. **갈라지면 조용히
갈라진다**(catalog.ts 주석). 장식이 업데이트로 계속 늘어나므로 먼저 합친다.

```jsonc
// game/shop/items.json — 유일한 원본
{
  "tierPrices": [10, 40, 150, 500, 1500],
  "items": [
    { "id": "monkey_01", "category": "monkey", "tier": 0, "name": { "ko": "갈색 원숭이", "en": "Brown Monkey" } },
    { "id": "monkey_02", "category": "monkey", "tier": 1, "steamItemDefId": 1, "name": { ... } },
    { "id": "banana_01", "category": "banana", "tier": 0, ... },
    { "id": "spark_01",  "category": "deco",   "tier": 3, "steamItemDefId": 10, "deco": { "kind": "trail" }, ... }
  ]
}
```

| 읽는 곳 | 방법 |
|---|---|
| 게임 `ShopCatalog` | 기동 때 `res://game/shop/items.json` 을 읽는다. 코드에 배열을 두지 않는다 |
| 스팀 매핑 `SteamInventoryService` | 같은 파일의 `steamItemDefId` 로 양방향 표를 만든다 |
| 서버 `catalog.ts` | 워커 번들이 JSON 을 import 한다 (`import items from "../../game/shop/items.json"`) |
| 스팀 `itemdefs.json` | `tools/make-itemdefs.py` 가 생성한다. 이름·설명·아이콘 URL·태그 |

- `steamItemDefId` 는 **한 번 정하면 바꾸지 않는다** — 이미 지급된 아이템이 그 번호로 스팀에 있다. 새 아이템은 뒤에 붙인다
- 기존 16종의 id·itemdefid(1~15)는 그대로 둔다. 분류만 바뀐다(§3)

## 4. 커서 레이어

### 4-1. 구성

```
CursorWindow (클릭 통과 투명 창, 192x192 — 예전 128)
 ├─ Deco      장식 (종류별: 뒤에 깔리는 후광 / 따라오는 잔상 / 옆에 떠 있는 물건)
 ├─ Banana    바나나 — 커서 끝에서 정해진 자리, 정해진 모양. 원숭이가 잡는 점(grip)이 여기 있다
 ├─ Monkey    원숭이 리그 — 손이 grip 에 붙어 있다
 └─ (시스템 커서는 OS 가 그린다)
```

- **바나나 템플릿**: 모든 바나나 변형은 같은 실루엣·같은 grip 점을 쓴다. 변형은 색·재질만 다르다 — 원숭이가
  어느 바나나에나 똑같이 매달릴 수 있어야 해서다. 변형은 기본 바나나 한 장에서 색을 바꿔 만든다(§6-3)
- **창 크기**: 원숭이가 흔들리고 떨어졌다 다시 잡는 폭이 128 을 넘는다. 192 로 키우고 A7 부하를 다시 잰다
- **추종**: 창은 지금처럼 커서를 따라간다(Spring). 흔들림은 창 안에서 리그가 한다 — 창을 흔들지 않는다

### 4-2. 원숭이 리그

| 부위 | 축(회전 중심) | 비고 |
|---|---|---|
| 몸통 | 목 | 리그의 뿌리. 손(grip)에 매달린 진자로 몸 전체가 돈다 |
| 머리 | 목 | 두리번, 끄덕 |
| 팔 L/R | 어깨 | 잡는 팔은 grip 을 향하고, 다른 팔은 자유 |
| 다리 L/R | 엉덩이 | 버둥, 늘어짐 |
| 꼬리 | 엉덩이 | **그림이 아니라 선(Line2D)으로** — 속도에 따라 휘고 늦게 따라온다. 색은 스킨이 정한다 |
| 얼굴 | 머리 위 | 표정 2~3종 (기본 / 신남 / 졸림) — 그림 교체 |

스킨 = 위 부위 그림 한 벌 + 꼬리 색 + 선택 장신구(모자 등). 폴더 `assets/cursor/monkey/<id>/`.

### 4-3. 장식 종류

| 종류 | 동작 | 예전 아이템 |
|---|---|---|
| `halo` | 커서 뒤에 깔림, 천천히 회전·맥동, 빛 셰이더 | halo_01/02, ring_01/02 |
| `trail` | 커서가 움직이면 뒤에 흩뿌려지고 사라짐 (파티클) | leaf, chunk, spark |
| `float` | 커서 옆에 떠서 둥실거림 — "뜬금없는 물건" | 새 아이템 |

종류는 `items.json` 의 `deco.kind` 와 파라미터로 정한다. 아이템마다 코드를 쓰지 않는다 — 새 장식은 그림 + JSON 한 줄.

## 5. 원숭이 상태 (반응형)

| 상태 | 들어가는 조건 | 모습 | 나가는 조건 |
|---|---|---|---|
| **매달림** (기본) | 커서 정지 | 한 손 또는 두 손으로 바나나를 잡고 숨쉬기, 가끔 두리번 · 다리 흔들기 · 바나나 냄새 맡기(대기 동작) | 이동 / 입력 / 오래 정지 |
| **흔들림** | 커서 이동 (보통 속도) | grip 을 축으로 진자 — 이동 반대로 기울었다가 되돌아옴. 꼬리가 늦게 따라옴 | 정지 후 흔들림이 잦아들면 매달림 |
| **버둥** | 빠른 이동 | 다리 버둥, 표정 놀람 | 속도가 떨어지면 흔들림 |
| **놓침 → 다시 잡기** | 아주 빠른 이동(순간 가속) | 손이 떨어져 아래로 처졌다가(창 안에서) 올라와 다시 잡음 | 다시 잡으면 매달림 |
| **반응** | 타건·클릭 (횟수만 — 헬퍼가 주는 것) | 빈 손을 들어 신남, 살짝 튕김. 연속 입력이면 리듬 타기 | 입력이 멈추면 매달림 |
| **졸기** | 입력·이동 없이 N분 | 바나나를 끌어안고 잠, 표정 졸림, **애니메이션을 멈춘다** | 어떤 입력이든 → 깸(짧은 기지개) |

- 입력은 **횟수만** 쓴다(§7-2) — 어떤 키인지 모르므로 반응은 "쳤다" 하나다
- 속도 문턱값·졸기 시간은 한 곳(표)에 모은다. 체감으로 조정한다
- **친구 창**: 친구의 커서 위치는 받지 않는다(C2 §2-1). 친구 원숭이는 매달림 · 반응(친구가 친 횟수) · 졸기만 한다

### 5-1. 성능 (A7: 유휴 CPU 1%, `PrivWS` 300MB)

지금 커서 창은 **움직이기만 하고 다시 그리지 않는다.** 움직이는 원숭이는 계속 그린다. 그래서:
- 커서 창만 초당 **15프레임** 상한 (메인 창과 별도)
- 매달림의 숨쉬기는 느리게, **졸기에서는 그리기를 멈춘다** — 오래 켜 두는 시간의 대부분이 졸기다
- 7단계에서 A7 과 같은 방법으로 다시 잰다 (`measure-renderers.ps1`, 커서 시뮬레이션 포함)

**2026-09-26 1차 측정 (디버그 빌드, 조건당 40초·워밍 10초 제외, 16코어 기준 %).** 기준(유휴 1%)을 반드시 지킬 조건은
아니라고 정했다(갑) — 얼마나 바뀌었는지만 기록한다.

| 조건 | B17 전 (`ed7ca61`) | B17 후 | 차이 |
|---|---|---|---|
| 커서 장식 켬 + 커서 정지 (두 번) | cpu 0.07~0.32% | cpu 0.66~0.70% | 약 +0.4~0.6%p |
| 커서 장식 켬 + 계속 이동(합성 경로) | cpu 0.04% | cpu 0.95% | 약 +0.9%p |
| 메모리 `priv` | 370~399MB | 413~415MB | 약 +15~45MB |

- 원인: 예전 커서 창은 **창만 옮기고 다시 그리지 않았다**(정지 그림). 이제는 숨쉬기로 초당 20번, 움직이면 매 프레임
  다시 그린다. 창도 128² → 224²
- 측정의 한계: "장식 끔" 조건을 넣었지만 세이브 옵션(장식 켬)이 이겨서 실제로는 꺼지지 않았다. 측정 중 실제 입력이
  섞여 정지 조건에도 반응(Cheer)이 끼었다 — 정지 값은 대략이다
- 더 줄여야 하면: 숨쉬기 20Hz → 10Hz, 졸기 전 멈춤을 3분 → 30초 정지 후로

### 6-2. 원숭이 부위

기본 원숭이 한 마리를 부위로 만든 뒤, 스킨은 **털 색 바꾸기 + 장신구**로 늘린다(털 영역만 색을 바꾸고 얼굴은
그대로). 오랑우탄처럼 실루엣이 다른 것은 부위를 따로 만든다. 부위 원본은 다음 순서로 시도한다.

1. 게임 본편 원숭이(`assets/_source/Monkey.png`, 품질이 가장 좋다)의 대기 프레임을 부위로 잘라내고, 가려졌던
   부분은 인페인팅으로 채운다 — 본편 원숭이와 같은 캐릭터가 커서에도 달리는 것이 가장 자연스럽다
2. 안 되면 ComfyUI 로 부위 시트를 뽑는다 (`_raw/monkey_arm.png`·`monkey_body.png` 는 예전 시도)
3. 둘 다 품질이 안 나오면 손으로 다듬거나 외주 — **여기가 일정 위험의 대부분이다**

### 6-3. 바나나 변형

기본 바나나 한 장(`banana_01`)을 정하고, 나머지는 그 그림의 색·재질만 바꿔 만든다(실루엣이 같아야 한다 — §4-1).
황금 · 은 · 얼룩 · 초코 · 얼음 등. 스크립트로 만든다(`tools/make-banana-variants.py`).

### 6-4. 장식 옮기기

잔상 6 · 바닥 4 의 그림은 그대로 쓰고 `deco.kind` 만 붙인다. 후광 종류는 셰이더로 빛을 더한다.

## 9. 3~4단계에서 한 것 (2026-09-26)

**원숭이는 머리만 그림이다.** 본편 원숭이 대기 프레임에서 목 위를 잘라(`tools/make-monkey-parts.py`) 스킨마다 털 색만
바꾸고(얼굴·귀 안쪽은 제외 — 살색 영역의 구멍을 메운 마스크), 몸통·팔·다리·손발·꼬리는 `MonkeyRig` 가 같은 그림체로
그린다. §6-2 의 1안(본편 원숭이를 부위로 자르기)을 해 보니 대기 프레임은 팔이 가슴 앞이라 잘라 내면 몸에 구멍이 나고
굽은 팔은 매달림 자세로 못 돌린다 — 그래서 머리만 가져왔다. 예전 ComfyUI 부위 시도(`_raw/monkey_arm`, `monkey_body`)는
그림체가 달라 못 쓴다.

**기본 자세는 한 팔 매달림.** 머리 너비 44px 에 두 팔로 매달리면 팔이 머리 뒤에 숨는다. 오른팔로 잡고 머리는 왼쪽으로
기울인다. 빈 왼팔이 반응을 맡는다.

| 파일 | 역할 |
|---|---|
| `shared/Cursor/MonkeySkin.cs` | `head.png` + `skin.json`(색, 목·눈 좌표) 읽기 |
| `shared/Cursor/MonkeyRig.cs` | 진자(잡은 손이 축, 커서 가속도가 걸린다) + 상태 + 그리기 + 표정 덧그리기. 초당 15번만 바뀌고 졸면 멈춘다 |
| `shared/Cursor/DecoView.cs` | 장식 종류 halo(회전·맥동·빛 한 겹) / trail(화면 좌표에 남는 입자) / float |
| `shared/Cursor/CursorOrnament.cs` | 장식 → 바나나 → 원숭이 한 벌. 커서 창과 친구 창(`Still` — 흔들림 없음)이 같이 쓴다 |
| `platform/CursorLayer.cs` | 창 128 → 224, 커서 끝은 창 안 (104, 40), 추종 기본 Direct. 셸이 입력 헬퍼의 타건 수를 넘긴다 |
| `--store-shot` | `rig_hang/move/stop/cheer` 프레임을 찍는다 (커서 시뮬레이션 경로) |

- `skin.json` 도 내보내기 `include_filter` 에 넣었다 (items.json 과 같은 이유)
- 새 그림을 만들면 `--import` 를 다시 돌려야 `ResourceLoader.Exists` 가 참이 된다 — 안 돌려서 원숭이가 통째로 안 보였다.
  그리고 `--import` 는 `GameRoot.cs` 를 또 탭으로 바꾼다 (되돌리고 diff 로 확인)
- 조정값(속도 문턱, 놓침 가속도, 진자 감쇠·최대각, 졸기 시간)은 `MonkeyRig` 맨 위 표 한 곳이다

### 9-1. 첫 체감 피드백으로 고친 것 (2026-09-26 갑)

| 피드백 | 원인 | 고친 것 |
|---|---|---|
| 흔들림이 급작스럽다 | 커서 가속도를 거르지 않고 그대로 진자에 넣었다 | 속도·가속도를 저역 통과(`AccelSmoothing`), 가속 상한 12000 → 6500, 결합 0.7, 중력 1600 → 1000(주기가 길어진다) |
| 매달린 팔이 따로 붙인 도형 같다 | 부위마다 "외곽선+채움" 을 따로 그려 이음매마다 외곽선이 생겼고, 어깨가 몸통 가장자리에 있었다 | **외곽선을 전부 먼저, 채움을 나중에** 그린다 - 한 덩어리 실루엣. 어깨를 몸통 안쪽으로 |
| 움직임이 탁탁 끊긴다 | 늘 초당 15번만 모양을 바꿨다 | 움직이는 동안(흔들림·반응·대기 동작·팔이 자리 잡는 중) 매 프레임, 가만히 숨만 쉴 때 초당 20번, 졸면 멈춤. 잔상 장식도 같은 규칙 |

### 9-2. 그리는 순서 (2026-09-26 갑)

- **빈 팔이 등 뒤로 가는 것처럼 보였다** — 9-1 에서 "외곽선 전부 → 채움 전부" 로 바꾸면서 빈 팔 채움이 몸통 채움보다
  먼저 그려졌다. 잡은 팔만 몸통과 한 덩어리로 두고, 빈 팔은 맨 끝에 자기 외곽선과 함께 몸 앞에 그린다
- **커서 창이 메인 창 뒤로 갔다** — 메인·친구·커서 창이 전부 "항상 위" 라 그들 사이 순서는 마지막에 활성화된 쪽이
  위다. `CursorLayer.BringToFront()` 가 `SetWindowPos(HWND_TOPMOST, 활성화 안 함)` 으로 다시 올린다 — 셸 0.5초 틱,
  메인 창 포커스, 친구 창 열 때
