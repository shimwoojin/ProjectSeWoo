## 0. 준비 — Godot .NET(mono) 빌드 받기 ★필수★

지금 `~/Downloads`에 있는 건 **표준 빌드**(`Godot_v4.7.2-stable_win64.exe`)라 C#을 못 읽는다.
[godotengine.org/download/windows](https://godotengine.org/download/windows) 에서 **`Godot_v4.7.2-stable_mono_win64.zip`** 을 받아 압축을 풀고, 그 안의 `Godot_v4.7.2-stable_mono_win64.exe`로 프로젝트를 연다.

- 표준 빌드는 단일 exe, mono 빌드는 **폴더째**다. exe만 빼내면 실행되지 않는다.
- .NET SDK는 이미 설치돼 있다 (9.0.301). .NET 8 런타임(8.0.17)도 있어서 `net8.0` 타깃이 그대로 돈다.
- 에디터 없이 컴파일만 확인하려면: `dotnet build ProjectSeWoo.csproj`

## 1. 실행

```
Godot_v4.7.2-stable_mono_win64.exe --path C:\EtcProjects\ProjectSeWoo
```

또는 mono 에디터에서 프로젝트를 열고 F5.

바탕화면 우하단에 Godot 아이콘이 떠 있고, 그 아래에 검은 HUD 패널이 보이면 성공이다.

> **HUD가 영어인 이유** — Godot 기본 테마 폰트에 한글 글리프가 없어서 한글은 두부(□)로 나온다.
> 게임 본편에서 한글 UI를 쓰려면 폰트를 별도로 번들해야 한다. 이것도 Week 0 확인 항목.

## 2. 조작

| 키 | 동작 | 무엇을 보려는 것인가 |
|---|---|---|
| 몸통 드래그 | 창 이동 | 드래그 이동이 매끄러운가 |
| `F1` | HUD 표시/숨김 | — |
| `F2` | 클릭 통과 On/Off | 끄면 창 전체가 마우스를 먹는다. 차이를 체감할 것 |
| `F3` | passthrough 갱신 모드 전환 | **godot#80098 플리커 재현 실험** |
| `F4` | 항상 위 On/Off | 전체화면 게임 위 동작 테스트용 |
| `F5` | FPS 캡 순환 (60 → 30 → 10 → 무제한) | 부하와 반응성의 균형점 찾기 |
| `F6` | 저전력 모드 On/Off | `OS.LowProcessorUsageMode` 효과 측정 |
| `F7` | 다음 모니터로 이동 | 멀티모니터 / DPI 좌표 검증 |
| `F8` | 클릭 영역 외곽선 표시 | passthrough 폴리곤이 실제로 어디인지 확인 |
| `F9` | 측정값을 클립보드로 복사 | 노션에 그대로 붙여넣기 |
| `F10` | 측정 리셋 | 설정 바꾸고 재측정할 때 |
| `Esc` | 종료 | — |

> 키가 안 먹으면 **몸통을 한 번 클릭해서 창에 포커스를 준다.** 무테 + 클릭 통과 창이라
> 포커스를 자동으로 못 가져오는 경우가 있다. 이것 자체가 기록할 관찰 결과다.

## 3. 측정 순서

### 3-1. 유휴 부하 (합격 기준: CPU < 1%, 메모리 < 150MB)

1. 실행 후 `F10`으로 리셋
2. **손대지 말고 10분 방치** (HUD의 `up` 값이 600초가 될 때까지)
3. `F9` → 클립보드 → 기록표에 붙여넣기
4. `F5`로 FPS 캡을 30, 10으로 바꿔가며 각각 반복

HUD의 `cpu avg`가 판정 기준이다. `peak`는 드래그 같은 순간 부하라 1%를 넘어도 된다.

> 작업관리자와 대조해볼 것. 값이 크게 다르면 `PerfProbe`의 계산이 틀린 것이니 그것부터 잡는다.

### 3-2. 플리커 재현 (godot#80098)

1. `F3`을 눌러 `update every-frame`으로 전환
2. 창 뒤로 **흰 배경**(메모장, 브라우저 빈 탭)을 두고 1~2분 관찰
3. 흰색 깜빡임이 보이는가?
4. 다시 `F3`으로 `on-change`로 되돌리고 같은 조건에서 관찰
5. HUD의 `writes` 카운터로 두 모드의 실제 호출 횟수 차이를 확인

| 결과 | 의미 |
|---|---|
| every-frame에서만 깜빡임 | **회피책이 통한다.** 폴리곤을 상태 변화 시에만 갱신하면 됨 → Go |
| 둘 다 깜빡임 | Godot 자체 문제. 창 크기를 고정하고 폴리곤을 아예 안 바꾸는 설계로 갈지 판단 필요 |
| 둘 다 안 깜빡임 | 4.7.2에서 수정됐다. 그대로 진행 |

### 3-3. 멀티모니터 / DPI

1. `F8`로 클릭 영역 외곽선 켜기
2. `F7`로 모니터를 옮겨가며, 외곽선 **안쪽**을 클릭하면 반응하고 **바깥**을 클릭하면 뒤 창이 눌리는지 확인
3. 배율이 다른 모니터(100% ↔ 125%/150%)에서 **외곽선과 실제 클릭 영역이 어긋나는지**가 핵심
4. HUD의 `dpi` / `scale` 값을 모니터별로 기록

> 어긋난다면 passthrough 좌표가 논리 픽셀이 아니라 물리 픽셀 기준이라는 뜻이다.
> `_win.ContentScaleFactor` 또는 `ScreenGetScale`로 보정해야 한다.

### 3-4. 전체화면 게임 위 동작

1. 보유한 게임을 **보더리스 풀스크린**으로 실행
2. 오버레이가 위에 보이는가 / 사라지는가
3. 게임 FPS가 떨어지는가
4. **배타적 풀스크린**으로 바꿔 다시 확인

> 배타적 풀스크린 위에 못 뜨는 건 정상이다. 버그가 아니라
> **"게임 실행 중엔 자동 숨김"이라는 기능 요구사항**으로 기획서에 반영한다.

### 3-5. 노트북 배터리

전원 뽑고 1시간 상주 → 설정 > 시스템 > 배터리 > 배터리 사용량에서 `ProjectSeWoo` 항목 확인.

